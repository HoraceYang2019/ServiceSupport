    05 Part Manufacturing — AI 專用程式說明

    對應內部 stage.id: layer-synthesis。本文根據使用者提供之十支程式原始檔與原總說明拆分，保留來源描述，不臆測外部數據。

    AI 閱讀與修改準則

    • 本文件對應 2026-10-10 上傳的程式版本，是閱讀程式和修改功能用的索引，不表示外部 NPZ/STL/CSV/NPY 已驗證存在。
    • 先依 stage-data.js 的 stage.id 確認模組，再追 app.js 的階段分支、run_dashboard.py 的 API、viewer 和 HTML/CSS。
    • 優先保留原始資料、欄位、單位與 API 契約；畫面示意、靜態預設指標不可當成真實運算成果。
    • 僅修改本階段必要檔案；共用檔案修改後，必須確認其他五個階段不受影響。
    • 注意 04／05 名稱交叉：04 的 ID 是 part-manufacturing，側欄名稱是 Layer Synthesis；05 的 ID 是 layer-synthesis，側欄名稱是 Part Manufacturing。不要自行對調。

    專案檔案角色

    檔案 作用
    stage-data.js 六階段 ID、名稱、初始內容與部分靜態範例數值
    app.js 前端階段切換、資料請求、顯示控制與 UI 更新
    run_dashboard.py 本機 HTTP 伺服器、外部資料讀取、API、數值與幾何處理
    index.html 畫面 DOM、viewer 容器、內嵌樣式
    track-npz-viewer.js 01/02 NPZ 的 phase/temperature 3D 顯示
    stl-viewer.js 共用 STL 3D 顯示、鏡頭、旋轉與標註
    feature-visuals.js Canvas 示意視覺圖
    reset.css、layout.css、components.css 基礎、版面與元件樣式

    05（layer-synthesis）— CSV Melt Pool／影像／完整 STL

    注意：側欄名稱顯示為 Part Manufacturing，程式中 stage.id 仍是 layer-synthesis；app.js 此分支標為「05」。

    目標與畫面

    中央改為 CSV Melt Pool Data；讀取 L0001–L0250 的 CSV 熔池長度／寬度資料。右上保留完整工件 STL 預覽，並在頁面顯示逐層鋪粉前、雷射後圖像。app.js 在該頁將 STL 模型以 rotation.x = -Math.PI/2 顯示，讓原始 Z-up 幾何對應 Three.js 畫面 Y-up。

    CSV 來源與欄位（0-based）

    • LAYER_FEATURE_CSV_DIR：預設 Windows ...\NIST\2. Slicing 目錄。
    • 層數範圍：LAYER_FEATURE_START_LAYER=1 至 LAYER_FEATURE_END_LAYER=250。
    • LAYER_FEATURE_COL_X=2：CSV 第 3 欄，X。
    • LAYER_FEATURE_COL_Y=3：CSV 第 4 欄，Y。
    • LAYER_FEATURE_COL_LENGTH=10：CSV 第 11 欄，Melt Pool Length (mm)。
    • LAYER_FEATURE_COL_WIDTH=11：CSV 第 12 欄，Melt Pool Width (mm)。

    注意：這是來源碼的固定欄位位置定義，若日後 CSV 更改欄位順序必須同步更新；不可根據欄名猜測而忽略索引。

    鋪粉前後影像

    • LAYER_POWDER_IMAGE_DIR 指向 ...\NIST\5. Global_image。
    • before powder recoating：鋪粉前的圖像目錄（名稱依原始檔案／程式註解）。
    • after laser exposure：雷射曝光後的圖像目錄。
    • 允許 .png、.jpg、.jpeg、.webp、.bmp。
    • 支援以環境變數調整目錄與指定固定影像。

    API 與 STL

    • /api/layer-feature/layers：有哪些層的資料／索引。
    • /api/layer-feature/layer/N：指定 layer 的 CSV 特徵。
    • /api/layer-feature/powder-image/N/before 與 /after：逐層圖片。
    • /layer-stl、/api/layer-stl-info：完整工件 STL（LAYER_STL_PATH）。

    AI 修改禁忌

    • 05 CSV 中熔池長寬原始單位註解為 mm；如要顯示 µm，明確乘以 1000，勿讓標題和數字單位不一致。
    • 05 的 CSV layer 指標與 04 的 NPZ layer 指標屬不同資料來源，不要任意共用 API。
    • 沒有真實逐層檔案時不能用示意動畫冒充測量／預測結果。

    API 快速索引

    /api/layer-feature/layers；/api/layer-feature/layer/N；/api/layer-feature/powder-image/N/{before,after}

    上述大括號表示路由集合的說明用縮寫，並非完整 URL；請依 run_dashboard.py 的實際路由與參數呼叫。

    交給 AI 的本階段工作指令

    請先閱讀本文件與同版本程式，確認 layer-synthesis 的實際資料來源、前端分支、API 和畫面元件，再修改第 05 階段。不得以其他階段資料取代本階段真實輸入；不得把前端示意或顯示校正寫成求解器結果。修改後說明涉及的函式、檔案、單位、資料格式和對其他五階段的相容性。

    AI 判讀來源的優先順序與防誤讀

    1. 目前程式有什麼：查 stage-data.js 的 number、id、name，再查 app.js 分支以及 run_dashboard.py 真正路由和輸入資料。
    2. 外部網站怎麼命名：採用對應 Additive Manufacturing 頁面的 01–06 階段順序；網站沒有細節的地方標示「未說明」，不要補寫成網站宣稱。
    3. 哪些是示意／靜態值：先辨別 stage-data.js 靜態 metrics、進度條與 log，不能把候選或 placeholder 數字當成模擬驗證。
    4. 如何修改：先確認牽涉的函式、前端欄位、HTTP 回傳、NPZ／STL／CSV 結構與單位，再修改。不要根據網站章節標題自行新增不存在的 Web Service 呼叫。
    5. 如何驗證：檢查本階段載入、API 回應、空資料／缺檔提示、視覺化與右側 metrics；共用元件變更時回歸檢查 01–06。
