    02 Layer Simulation — AI 專用程式說明

    對應內部 stage.id: layer-simulation。本文根據使用者提供之十支程式原始檔與原總說明拆分，保留來源描述，不臆測外部數據。

    AI 閱讀與修改準則

    • 本文件對應 2026-10-10 上傳的程式版本，是閱讀程式和修改功能用的索引，不表示外部 NPZ/STL/CSV/NPY 已驗證存在。
    • 先依 stage-data.js 的 stage.id 確認模組，再追 app.js 的階段分支、run_dashboard.py 的 API、viewer 和 HTML/CSS。
    • 優先保留原始資料、欄位、單位與 API 契約；畫面示意、靜態預設指標不可當成真實運算成果。
    • 僅修改本階段必要檔案；共用檔案修改後，必須確認其他五個階段不受影響。
    • 注意 04／05 名稱交叉：04 的 ID 是 part-manufacturing，側欄名稱是 Layer Synthesis；05 的 ID 是 layer-synthesis，側欄名稱是 Part Manufacturing。不要自行對調。

    02 Layer Simulation

    目標與功能

    Layer Simulation 提供 A、B、A+B 三種切換模式，每組具有獨立 NPZ 和 STL，呈現 Phase / Temperature 隨時間變化。另有第四格額外 STL；分析區除 01 的熔池指標外，還包含 Internal Void Ratio、Void Volume，以及 STL 上表面水平線平均高低差。

    三組資料配對（不可錯接）

    模式 NPZ 設定 對應 STL 變數 API base
    A LAYER_SIM_NPZ_DIR_A + LAYER_SIM_NPZ_PATTERN_A LAYER_SIM_STL_PATH_A /api/npz/layer/a
    B LAYER_SIM_NPZ_PATH_B（程式固定絕對路徑） LAYER_SIM_STL_PATH_B /api/npz/layer/b
    A+B LAYER_SIM_NPZ_DIR_AB + LAYER_SIM_NPZ_PATTERN_AB LAYER_SIM_STL_PATH_BOTH /api/npz/layer/ab

    預設 NPZ：A 為 249global_thermal_phase_all_timeseries.npz；B 為 250global_thermal_phase_all_timeseries.npz；A+B 為 249_250_AB_global_thermal_phase_all_timeseries.npz。另有 LAYER_SIM_STL_PATH_EXTRA 固定獨立 STL。B 使用固定路徑，不讀 LPBF_LAYER_NPZ_DIR_B 或 LPBF_LAYER_NPZ_PATTERN_B 環境變數。

    API 與幾何處理

    三組各自支援 /meta、/snapshot?index=N、/temperature?index=N、/track-analysis?index=N、/diagnostic?index=N；另外有 /layer-sim-stl-b、/layer-sim-stl-both、/layer-sim-stl-extra 等 STL 端點與各組 *-info 路由。舊 /api/npz/layer/meta 依相容邏輯指向 A。

    大型 STL 預覽存在三角形數上限（預設 750000），使用 vertex clustering 建立預覽用壓縮表面；原始 STL 檔案不被更改。上表面標記依 5×5 XY 分區取得樣點。高低差先沿 Y 設定水平線，再沿 X 求每條線 max(Z) - min(Z) 後取平均，預設 3 條。

    溫度顯示特殊處理

    LAYER_SIM_TEMPERATURE_DISPLAY_OFFSET_K = -1000.0：此為 02 Dashboard/API 的顯示校正，原始 NPZ 不會被改寫。AI 分析熱傳真實數值時應使用原始溫度，若引用網頁顯示溫度應說明偏移設定。

    AI 修改禁忌

    • 切換 A/B/A+B 時，NPZ、STL、分析值必須同步切換。
    • 第四格 STL 是另一個獨立模型，不能跟 A/B/A+B 綁在同一來源。
    • 顯示校正不能混入原始模擬計算，也不能未告知就刪除／套用至 01。

    API 快速索引

    /api/npz/layer/{a,b,ab}/{meta,snapshot,temperature,track-analysis,diagnostic}

    上述大括號表示路由集合的說明用縮寫，並非完整 URL；請依 run_dashboard.py 的實際路由與參數呼叫。

    交給 AI 的本階段工作指令

    請先閱讀本文件與同版本程式，確認 layer-simulation 的實際資料來源、前端分支、API 和畫面元件，再修改第 02 階段。不得以其他階段資料取代本階段真實輸入；不得把前端示意或顯示校正寫成求解器結果。修改後說明涉及的函式、檔案、單位、資料格式和對其他五階段的相容性。

    AI 判讀來源的優先順序與防誤讀

    1. 目前程式有什麼：查 stage-data.js 的 number、id、name，再查 app.js 分支以及 run_dashboard.py 真正路由和輸入資料。
    2. 外部網站怎麼命名：採用對應 Additive Manufacturing 頁面的 01–06 階段順序；網站沒有細節的地方標示「未說明」，不要補寫成網站宣稱。
    3. 哪些是示意／靜態值：先辨別 stage-data.js 靜態 metrics、進度條與 log，不能把候選或 placeholder 數字當成模擬驗證。
    4. 如何修改：先確認牽涉的函式、前端欄位、HTTP 回傳、NPZ／STL／CSV 結構與單位，再修改。不要根據網站章節標題自行新增不存在的 Web Service 呼叫。
    5. 如何驗證：檢查本階段載入、API 回應、空資料／缺檔提示、視覺化與右側 metrics；共用元件變更時回歸檢查 01–06。
