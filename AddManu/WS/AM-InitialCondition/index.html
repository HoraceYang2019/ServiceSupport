    A. 材料設定

    material_gpu.py｜GPU 材料物性查表

    對應版本：LPBF 26-Step GPU v2.9。以實際 Python 原始碼為準；本文件不代表已通過 GPU 實測或數值驗證。

    1. 程式說明 / Responsibility

    以 GPU 插值取得 cp(T)、rho(T)、k(T) 與含氣相背景的 k_cell。

    計算流程： CuPy float32 三維場。

    2. Input（輸入）

    以下為原始碼函數簽章，名稱與參數順序直接對照 Python：

    cp_metal(T)

    Input 含義／單位
    T 溫度 K，GPU 3D float32

    Output（回傳）：比熱 cp(T) [J/(kg K)]

    原始回傳表達式： - return cp.interp(T,_T,_CP).astype(cp.float32)

    rho_metal(T)

    Input 含義／單位
    T 溫度 K，GPU 3D float32

    Output（回傳）：密度 rho(T) [kg/m³]

    原始回傳表達式： - return cp.interp(T,_T,_R).astype(cp.float32)

    k_metal(T)

    Input 含義／單位
    T 溫度 K，GPU 3D float32

    Output（回傳）：導熱係數 k(T) [W/(m K)]

    原始回傳表達式： - return cp.interp(T,_T,_K).astype(cp.float32)

    k_cell(T, F)

    Input 含義／單位
    T 溫度 K，GPU 3D float32
    F 金屬體積分率 VOF [0,1]，GPU 3D float32

    Output（回傳）：有效 voxel 導熱係數 [W/(m K)]

    原始回傳表達式： - return (m.ARGON_K+cp.clip(F,0,1)*(k_metal(T)-m.ARGON_K)).astype(cp.float32)

    3. Output（輸出）與副作用

    • 直接輸出： 上述函數回傳資料。
    • 檔案寫入： 此模組本身不負責一般 NPZ 寫入。

    4. 程式依賴與 GPU/CPU 邊界

    • 專案內相依模組：material_parameters.py。
    • 主要 GPU 場使用 CuPy；float(...)、.get()、cp.asnumpy() 可能產生同步。不要在每個 voxel 的 Python 迴圈中逐一搬運。
    • material_parameters.py 與 process_parameters.py 在 CPU 設定材料與製程常數；GPU 計算模組讀取這些常數。

    5. 物理公式／數值實作對照

    此檔案的公式、係數及離散方式請以相同版本 .py 的實作為準，勿從模組名稱推斷未實作功能。

    6. AI 修改約束 / AI Editing Rules

    1. 查表值不是使用流體解自動識別的新物性，超出表格範圍需驗證。
    2. 修改函數名稱、輸入或回傳時，需同步搜尋所有呼叫者並更新此 MD。
    3. 維持 F（金屬 VOF）、fL（液相率）、alphaL=F*fL 三者的不同含義。
    4. GPU 欄位優先使用 CuPy float32；不可為了加速而省略必要的 CFL、散度與守恆檢查。
    5. 若程式本身未實作特定物理功能，不得在 AI 說明中宣稱已實作。

    7. 程式位置及檢查

    • 原始碼：../material_gpu.py
    • 此文件是 v2.9 程式的閱讀指南。若程式更新版本，應重新檢查 Input/Output。

    B. Ti64 材料常數與物性表

    3. Output（輸出）與副作用

    4. 程式依賴與 GPU/CPU 邊界

    C. 體素粉床幾何

    geometry_gpu.py｜體素粉床幾何

    對應版本：LPBF 26-Step GPU v2.9。以實際 Python 原始碼為準；本文件不代表已通過 GPU 實測或數值驗證。

    1. 程式說明 / Responsibility

    讀取 solid_mask.npy 並建立固定 Cartesian 網格的初始金屬占有率 F。

    計算流程： 輸入 CPU mask，轉成 GPU float32 F；為粉床與基板填充。

    2. Input（輸入）

    以下為原始碼函數簽章，名稱與參數順序直接對照 Python：

    load_F()

    Input 含義／單位
    無顯式輸入 可能讀取全域設定或模組資料

    Output（回傳）：F: cupy.ndarray float32，金屬 VOF 初始佔據率

    原始回傳表達式： - return cp.asarray(F)

    coordinates()

    Input 含義／單位
    無顯式輸入 可能讀取全域設定或模組資料

    Output（回傳）：(x,y,z): 三個 GPU 一維座標向量（m）

    原始回傳表達式： - return x,y,z

    3. Output（輸出）與副作用

    • 直接輸出： 上述函數回傳資料。
    • 檔案寫入： 此模組本身不負責一般 NPZ 寫入。

    4. 程式依賴與 GPU/CPU 邊界

    • 專案內相依模組：process_parameters.py。
    • 主要 GPU 場使用 CuPy；float(...)、.get()、cp.asnumpy() 可能產生同步。不要在每個 voxel 的 Python 迴圈中逐一搬運。
    • material_parameters.py 與 process_parameters.py 在 CPU 設定材料與製程常數；GPU 計算模組讀取這些常數。

    5. 物理公式／數值實作對照

    此檔案的公式、係數及離散方式請以相同版本 .py 的實作為準，勿從模組名稱推斷未實作功能。

    6. AI 修改約束 / AI Editing Rules

    1. VOF F 可以在後續運輸，voxel 網格本身固定。
    2. 修改函數名稱、輸入或回傳時，需同步搜尋所有呼叫者並更新此 MD。
    3. 維持 F（金屬 VOF）、fL（液相率）、alphaL=F*fL 三者的不同含義。

    D. 時間步長

    timestep_gpu.py — 固定時間步長 v3.3

    功能

    主模擬目前不啟用自適應時間步長。每步使用 process_parameters.FIXED_DT。舊的 choose()、choose_cooling_thermal() 為相容性保留，但主迴圈不呼叫。

    Input

    • validate_fixed_dt(dt, vmax, force_accel)：dt [s]、vmax [m/s]、force_accel [m/s²]。
    • limits(vmax)：上一步速度最大值 [m/s]。

    Output

    • validate_fixed_dt(...)：正常回傳 None；超出估計穩定限制時丟出 RuntimeError，不會調整 dt。
    • limits(...)：各時間步長限制（秒）的字典。

    公式與安全

    估計 dt_thermal、dt_adv、dt_viscous、dt_capillary、dt_force。每 LPBF_FIXED_DT_CHECK_EVERY 步檢查；超標就中止。

    AI 修改限制

    不要將超標的固定步長偷偷調小，也不要刪除安全檢查。這不是完整數值穩定性證明，使用者需對 0.2、0.4 ns 等設定做收斂測試。
